# Drivers arquitectónicos

Requisitos, atributos de calidad y restricciones con mayor impacto en la arquitectura, y por qué la condicionan.

| ID | Driver arquitectónico | Origen | ¿Por qué influye en la arquitectura? |
| :--- | :--- | :--- | :--- |
| **DA01** | El sistema debe soportar picos de consulta concurrente (≈ 1,000 usuarios en la publicación de notas y en campañas de admisión) y de generación documental sin degradar el flujo web. | AC01 – Rendimiento; AC02 – Disponibilidad; AC03 – Escalabilidad | Exige una capa de aplicación sin estado que escale agregando instancias, una estrategia de lectura que abarate cada consulta repetida (notas consolidadas precalculadas, consultas agregadas, índices y caché del cliente) y sacar la generación intensiva de libretas y reportes del camino de la petición. |
| **DA02** | Los expedientes digitales y probatorios de menores deben resguardarse bajo estricta privacidad. | AC04 – Seguridad y Privacidad; RC05 – Almacenamiento con URLs temporales | Condiciona que los datos y documentos de menores solo sean accesibles para usuarios autenticados y autorizados (por rol y por propiedad), que los archivos no se expongan públicamente ni se guarden en el servidor web, y que su descarga use enlaces temporales de corta duración (RC05). |
| **DA03** | Cada calificación y cambio de estado documental debe ser inalterable y auditable legalmente. | AC05 – Integridad y Trazabilidad; RC04 – Base de datos relacional ACID | Obliga a que el registro de auditoría ocurra en la misma transacción que el cambio de datos, con fecha, hora, usuario e IP, y que la inalterabilidad la garanticen los privilegios de la base de datos y no solo el código de la aplicación. |
| **DA04** | El sistema debe desacoplar la interfaz web de la lógica de evaluación y persistencia. | RC03 – API REST; AC06 – Mantenibilidad | Limita la comunicación entre la interfaz y el backend a una API REST sobre HTTPS y exige organizar el backend en módulos con fronteras claras, de modo que las reglas de evaluación, los catálogos y los proveedores técnicos puedan cambiar de forma independiente. |
| **DA05** | La plataforma debe permitir a los apoderados supervisar múltiples hijos desde un único acceso. | RF01 – Vista familiar; AC04 – Seguridad y Privacidad | Modela la relación apoderado–estudiante como N:M (un estudiante puede tener más de un apoderado y un apoderado varios estudiantes) y exige validar en cada consulta que el estudiante pertenezca al apoderado autenticado. |
| **DA06** | El sistema debe generar reportes oficiales compatibles con el registro reglamentario en SIAGIE. | RC06 – SIAGIE; RC08 – Horizonte MVP | Condiciona la arquitectura de reportería para generar sábanas de datos consolidadas en formato Excel (.xlsx) estructuradas según las normas del Ministerio de Educación. |
