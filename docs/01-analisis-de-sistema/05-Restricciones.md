# Restricciones

Condiciones técnicas, normativas y de plazo que acotan el diseño del sistema.

| ID | Restricción | Descripción | Origen |
| :--- | :--- | :--- | :--- |
| **RC01** | **Aplicación web multiplataforma** | El sistema debe desarrollarse como una aplicación web responsiva accesible mediante navegadores web modernos de escritorio (Chrome, Firefox, Edge, Safari) y smartphones móviles (resolución mínima 360x640). | Necesidad de los usuarios (acceso desde móvil y escritorio) |
| **RC02** | **Control de versiones** | El código fuente del proyecto debe gestionarse obligatoriamente utilizando Git y mantenerse alojado en un repositorio institucional compartido. | Requisito del curso |
| **RC03** | **API RESTful desacoplada** | La comunicación entre la capa de presentación (Frontend) y los servicios del backend debe realizarse mediante una API REST protegida por HTTPS/TLS obligatorio. | Decisión propia del proyecto (ver ADR-001) |
| **RC04** | **Base de Datos Relacional ACID** | La persistencia de datos debe utilizar PostgreSQL 16 o superior (la versión 16 tiene soporte oficial hasta nov-2028), garantizando restricciones de integridad referencial, transacciones atómicas y el uso de la extensión `pgcrypto` para cifrar columnas sensibles. El hash de contraseñas se realiza en la aplicación, no en la base de datos. | Decisión propia del proyecto (ver ADR-001) |
| **RC05** | **Almacenamiento de Archivos con URLs Temporales** | Los archivos generados (libretas y actas) no deben guardarse directamente en el servidor web ni de manera pública; deben custodiarse en un almacenamiento de objetos privado con acceso exclusivo mediante URLs firmadas de corta duración (TTL 15 min). La misma regla aplicará a los documentos probatorios cuando vuelva admisión. | Decisión propia del proyecto (ver ADR-002) |
| **RC06** | **Compatibilidad Formato SIAGIE sin API directa** | Por decisión de alcance, el MVP no incluye conexiones automatizadas directas vía APIs con SIAGIE. La interoperabilidad se restringe a llenar en Excel (.xlsx) la plantilla que el propio SIAGIE genera por periodo, grado y sección, y a cargar en el portal su nómina. **Bloqueo:** el formato exacto se define con una plantilla real y una nómina con datos ficticios, aún no disponibles. | Alcance del MVP |
| **RC07** | **Límites de Carga Documental** | Aplica cuando vuelva admisión: la mesa de partes virtual debe validar tipos MIME estrictos (PDF o imágenes legibles) y restringir el tamaño máximo por archivo a 5 MB (impuesto en la política de subida firmada) para preservar rendimiento y almacenamiento. En el MVP no se suben archivos al portal. | Decisión propia del proyecto (ver ADR-002) |
| **RC08** | **Horizonte Temporal y Alcance del MVP (12 semanas)** | **Plazo:** ciclo estricto de desarrollo de 12 semanas (≈ 3 meses). **Fuera de alcance:** matrícula, admisión, traslados y mesa de partes (pendientes para versiones siguientes), pasarelas de pago y procesos financieros, subida de trabajos de estudiantes, control biométrico de asistencia, entornos LMS, chat en tiempo real e integración directa por API con SIAGIE (RC06). | Requisito del curso y decisión de alcance |
