# Drivers arquitectónicos

Requisitos, atributos de calidad y restricciones con mayor impacto en la arquitectura, y por qué la condicionan.

| ID | Driver arquitectónico | Origen | ¿Por qué influye en la arquitectura? |
| :--- | :--- | :--- | :--- |
| **DA01** | El sistema debe soportar el uso diario de seguimiento y los picos de consulta concurrente (≈ 1,000 usuarios, por ejemplo al publicar libretas) y de generación documental sin degradar el flujo web. | AC01 – Rendimiento; AC02 – Disponibilidad; AC03 – Escalabilidad | Exige una capa de aplicación sin estado que escale agregando instancias, una lectura barata por estudiante (consultas agregadas, índices, paginación y caché del cliente) y sacar la generación intensiva de libretas y reportes del camino de la petición. |
| **DA02** | Los datos académicos, observaciones y archivos de menores deben resguardarse bajo estricta privacidad. | AC04 – Seguridad y Privacidad; RC05 – Almacenamiento con URLs temporales | Condiciona que los datos de menores solo sean accesibles para usuarios autenticados y autorizados (por rol y por propiedad), que los accesos queden registrados, que los archivos no se expongan públicamente ni se guarden en el servidor web, y que su descarga use enlaces temporales de corta duración (RC05). |
| **DA03** | Cada cambio de calificativos publicados, niveles y estados debe ser inalterable y auditable legalmente. | AC05 – Integridad y Trazabilidad; RC04 – Base de datos relacional ACID | Obliga a que el registro de auditoría ocurra en la misma transacción que el cambio de datos, con fecha, hora, usuario, IP y valores, y que la inalterabilidad la garanticen los privilegios de la base de datos y no solo el código de la aplicación. |
| **DA04** | El sistema debe desacoplar la interfaz web de la lógica de evaluación y persistencia. | RC03 – API REST; AC06 – Mantenibilidad | Limita la comunicación entre la interfaz y el backend a una API REST sobre HTTPS y exige organizar el backend en módulos con fronteras claras, de modo que las reglas de evaluación, los catálogos y los proveedores técnicos puedan cambiar de forma independiente. |
| **DA05** | La plataforma debe permitir a los apoderados seguir a múltiples hijos desde un único acceso. | RF01 – Vista familiar; AC04 – Seguridad y Privacidad | Modela la relación apoderado–estudiante como N:M (un estudiante puede tener más de un apoderado y un apoderado varios estudiantes) y exige validar en cada consulta que el estudiante pertenezca al apoderado autenticado. |
| **DA06** | El sistema debe generar automáticamente el Excel para el SIAGIE desde lo que el docente ya registró. | RC06 – SIAGIE; RF16 – Excel SIAGIE; AC07 – Usabilidad docente | Es el principal ahorro para el docente. Exige que los niveles confirmados se guarden con la estructura que pide la plantilla oficial, y aislar su formato para ajustarlo cuando esta cambie. |
| **DA07** | El registro docente debe tener baja fricción. | AC07 – Usabilidad docente; RF06 – Cuadrícula; RF23 – Actividades | Sin registro continuo no hay seguimiento. Exige una cuadrícula móvil con guardado masivo, nivel sugerido y separación entre el seguimiento diario y el nivel oficial del trimestre. |
